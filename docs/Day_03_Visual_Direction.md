# AfterMotion Day 3 视觉方向 V2

## 概念：Recovery in Motion / 动态恢复

V2 参考用户提供的健康 Dashboard：用超粗标题、黑白高对比、荧光焦点色、深青数据面板和大圆角模块，建立更年轻、更有运动能量的界面。

AfterMotion 不直接复制桌面 Dashboard。移动端仍保持单列任务流，让用户在测量时一次只处理一个主要动作。

```text
大胆运动编辑感 45%
健康科技可信度 35%
清晰平静的任务体验 20%
```

## 从参考图提取的视觉语言

保留黑色超粗标题、荧光黄绿色焦点、白色大圆角卡片、深青数据区域、浅冰蓝背景、圆形图标容器，以及数字与状态之间明显的大小对比。

不会直接照搬桌面双栏、侧边栏和单屏大量 Dashboard 模块；饮水产品的照片素材、复杂刻度和装饰性微型图表也不会进入测量主流程。

## 色彩方向

以黑白高对比建立内容骨架，深青色承载数据，荧光黄绿色只负责关键焦点。

| Token | 色值 | 用途 |
|---|---:|---|
| Editorial Black | `#0B1112` | 超粗标题、核心数字、主要按钮 |
| Signal Teal | `#087885` | 品牌、恢复数据、选中状态 |
| Deep Data Teal | `#087380` | 图表和重点数据面板 |
| Signal Lime | `#E7FF45` | 当前步骤、重点数字、关键行动 |
| Soft Teal | `#D5EFF2` | 选中背景、恢复状态浅底 |
| App Background | `#EAF6F8` | 页面背景，浅冰蓝 |
| Surface | `#FFFFFF` | 卡片和主要容器 |
| Secondary Text | `#4D6064` | 描述与标签 |
| Border | `#D3E4E7` | 分隔线和描边 |

### 荧光焦点色规则

Signal Lime 可用于当前 Recovery checkpoint、Activity 正在进行、单页最重要行动，以及图表中最需要关注的数据。它不用于长文本、错误提示或大面积页面背景；荧光底始终配黑色文字。

医疗和设备状态继续使用独立语义色，荧光色不代表“安全”或“正常”。同一屏幕原则上只设置一个明显的荧光主焦点。

### 语义色

| 状态 | 主色 | 浅色背景 |
|---|---:|---:|
| Complete / Success | `#237A5A` | `#E0F2E9` |
| Attention / Warning | `#A9651B` | `#FAEBD6` |
| Error / Critical | `#B64A43` | `#F8E3E1` |
| Information | `#376F9F` | `#E2EEF8` |

风险和状态不能只使用颜色，必须同时显示文字标签，后续增加图标时再加入形状提示。

### 左右侧

- Left：蓝色 `#3976A8`；
- Right：暖棕橙 `#B8643F`。

颜色只作为辅助。页面必须同时显示 Left / Right 或方向图标。受伤侧使用 `Injured side` 文字标签，不用红色暗示受伤或危险。

## 字体方向

阶段一使用系统字体，避免引入字体下载和加载风险：iOS 使用 San Francisco，Android 使用系统 Sans。

| 类型 | 字号 / 行高 | 字重 | 场景 |
|---|---|---|---|
| Display | 40 / 44 | 800 | 计时、核心恢复结果 |
| Page Title | 32 / 36 | 800 | 页面标题 |
| Heading | 22 / 28 | 700 | 信息组标题 |
| Subheading | 17 / 23 | 600 | 卡片标题 |
| Body | 16 / 24 | 400 | 正文说明 |
| Body Strong | 16 / 24 | 600 | 数据值和重要行 |
| Caption | 13 / 18 | 500 | 单位、时间和辅助信息 |
| Overline | 12 / 16 | 700 | 阶段标签 |
| Metric | 42 / 46 | 800 | 温度、计时、恢复时间 |

标题使用参考图中的紧凑编辑感，移动端最多两行。局部关键词可以放在荧光胶囊中，但不能让每个标题都高亮。

## 空间、圆角与阴影

使用 4pt 基础网格：`4 / 8 / 12 / 16 / 24 / 32 / 48`。

- 页面水平边距：24；
- 卡片内部间距：16–20；
- 卡片之间：16；
- 相关文字间距：4–8；
- 不同信息组：24–32。

圆角规则：

- 小标签和输入项：10；
- 按钮：14；
- 数据卡片：20；
- 重点摘要卡片：28；
- Status Tag：胶囊圆角。

默认卡片主要使用描边。阴影仅用于重点摘要或悬浮操作，避免每张卡片都有浓重阴影。

参考图中的多面板 Dashboard 在移动端转化为纵向模块：大胆页面标题 → 当前行动荧光焦点 → 白色任务卡片 → 深青数据卡片 → 次级说明。保持一屏一个主要视觉焦点，避免卡片彼此竞争。

## 组件气质

- 主按钮默认使用黑底白字；当前关键步骤可以使用荧光底黑字；高风险操作使用白底红字或浅红背景。
- Status Tag 使用胶囊形，Active 使用荧光色，Complete 使用绿色，Pending 使用灰蓝，并始终包含文字。
- 常规结果使用白色卡片；Activity Load 和 Recovery Curve 等重点数据使用深青面板、白色文字和少量荧光关键值。
- 图表用深青或蓝色呈现基础数据，荧光色只强调当前点、峰值或受关注系列；缺失数据使用虚线和文字标记。

## 图标与图形语言

- 使用简洁线性图标，推荐 1.75–2px 线宽；
- 设备、温度、时间、运动和方向图标必须具有稳定语义；
- 图标不能单独承担关键含义，必须配合文字；
- 图表使用圆角线段和清晰节点，不使用发光效果；
- 动画仅用于测量进度、连接变化和完成反馈。

## 页面结构原则

```text
阶段标签
→ 清晰页面标题
→ 当前状态或推荐行动
→ 主要数据/任务卡片
→ 单一主要按钮
→ 次级操作与安全说明
```

Session Overview 使用纵向阶段卡片，当前阶段带荧光状态；Measurement 强调侧别、粗进度和大号读数；Activity 使用大号计时和深青实时数据面板；Recovery 用荧光色强调当前时间点；Summary 先给清晰结论，再展示深青趋势卡片和左右膝对比。

## 插画与图像

后续高保真页面可加入一张核心视觉资产，例如抽象膝关节轮廓、运动人物剪影或由数据点组成的身体运动轨迹。只用于 Training Hero、Activity 或空状态，不使用写实伤口、医学扫描或疼痛视觉，也不能遮挡测量操作。

阶段一暂不生成图片，先通过 UI Kit 验证视觉语言。

## 明确避免

- 把桌面参考图直接压缩成拥挤的手机 Dashboard；
- 每张卡片都使用荧光色；
- 用荧光色表示安全或医学正常；
- 黑底荧光色覆盖整个 App；
- 用红色表示受伤侧；
- 过多渐变、玻璃拟态和发光效果；
- 把所有数据都做成仪表盘；
- 只用颜色区分左右侧或异常状态；
- 使用“安全、正常、受伤、炎症”等诊断式视觉标签。
